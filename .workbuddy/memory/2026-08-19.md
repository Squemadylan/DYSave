# DYSave（圆圆解析）Cookie 自动获取方案 — 2026-08-19

## 真机环境（当前）
- **设备**: FY241601054F（物理机，Android）
- **Root**: 用户已用 **APatch** 给 DYSave (`com.douyin.downloader`) 授权 Root。
- **验证**: `su -c 'id'` → `uid=0(root) gid=0(root)`；DYSave UID=10581；`/data/adb/ap/` 存在。
- **APatch 坑**: `su -c 'ls -d /data/data/pkg/app_webview*/Cookies'` 会吞掉 `*` 通配符 → 改用 `find /data/data/$pkg -name Cookies`。
- **已安装**: debug APK v1.0.4（含「Root 一键获取」按钮），构建用 Gradle 9.0.0（AGP 8.7.3 需 ≥8.9）。

## 核心实现
- 新增 `data/remote/RootCookieFetcher.kt`：`@Singleton`，用 `su` 把目标包 WebView 的 `Cookies` SQLite 库 `cat` 出来，查 `cookies(host_key,name,value)` 表，按域名拼成 `name=value; ...` 字符串。su 候选路径：`su` / `/data/adb/ap/bin/su` / `/system/bin/su` / `/system/xbin/su`。
- `ProfileViewModel.kt`：注入 `RootCookieFetcher`，暴露 `isRootAvailable()` / `fetchDouyinCookieViaRoot()` / `fetchXhsCookieViaRoot()`。
- `ProfileScreen.kt`：`XhsCookieEditor` / `DouyinCookieEditor` 各加 `Root 一键获取` 按钮（`YuanButton` + `loading` + Toast）。

## 抖音 Cookie —— 已验证可用 ✅
- 抖音实际 Cookies 路径：`/data/data/com.ss.android.ugc.aweme/app_webviewbytedance_com.ss.android.ugc.aweme/Cookies`（ByteDance 后缀目录，非 `app_webview_com.ss.android.ugc.aweme`）。
- 一键提取 **162 条 douyin.com Cookie**，含 `sessionid_ss` / `sid_guard` / `sid_tt` / `ttwid`（完整登录态）。无需在 DYSave 内再登录。

## 小红书 Cookie —— 按钮已就绪，需一次性登录 ⚠️
- 小红书 App (`com.xingin.xhs`) **不暴露 Web Cookie**（数据目录 grep 无 `web_session`），无法从 App 直接 root 读取登录态。
- 方案：读本 App 自己的 WebView (`com.douyin.downloader/app_webview/Default/Cookies`)。需用户先在 DYSave「登录获取」完成一次小红书网页登录（含验证码），`web_session` 等即落入本 App WebView，随后「Root 一键获取」即可自动捕获完整会话。
- 当前 DYSave WebView 仅含匿名 Cookie（无 `web_session`），故 XHS 按钮需该一次性登录后才能产出有效 Cookie。

## 用户待办（无法自动化的部分）
1. 真机打开 DYSave → 我的 → 小红书 Cookie → 点「登录获取」→ 完成小红书网页登录（验证码）。
2. 返回后点「Root 一键获取」自动填入 Cookie。
3. 抖音：直接点「Root 一键获取」即可（前提是抖音 App 已登录）。

- **编译错误修复**：`RootCookieFetcher.kt` 升级版加了 `lastError`（`String?`）诊断字段，`Log.w/e(TAG, lastError)` 因传 nullable 报 4 处 type mismatch（行 83/94/123/138）。改为先 `val msg = "..."` 再 `lastError = msg; Log.w(TAG, msg)`。
- **小红书短链 `xhslink.cn` 解析失败修复**：`LinkPlatformDetector.detect()` 只认 `xhslink.com`，用户粘贴的是 `xhslink.cn`（`.cn`）→ 命中 `UNKNOWN` → `ContentRepository` 抛 `UnsupportedPlatform` → UI 显示"解析失败，请检查链接"。已在 XHS 分支加 `"xhslink.cn" in url`。下游 `XIAOHONGSHU` 分支走 `fiftyTwoApi.parse(platform, url, xhsCookieRaw=cookie)`，短链交 52API 解析。
- **抖音 Root 一键获取返回 null —— 已定位真因并修复（16:01 打包安装）**：
  - **真因（真机 nsenter 实证）**：Android 11+ 的「App 数据隔离」让每个 App 处于独立 mount 命名空间。App 内 spawn 的 su 继承本 App 命名空间，在其中 `ls /data/data/com.ss.android.ugc.aweme` → "No such file or directory"（别的 App 目录被隐藏）。所以能读**自己**目录（小红书 OK），读**抖音**读不到。
  - **排除项**：不是 SELinux MLS 分类问题；APatch 的 su **不支持 `-Z/--context`**（实测 Unrecognized option）。
  - **修复**：`RootCookieFetcher.runSuBytes` 改为优先 `su -M -c`（`--mount-master`，强制全局 mount 命名空间），失败再回退普通 `-c`。su 路径候选 `su` / `/system/bin/su` / `/system/xbin/su` / `/data/adb/ap/bin/su`。
  - **验证（decisive）**：`nsenter -t <DYSave_pid> -m -- su -c 'cat 抖音Cookies|wc -c'` → **0**；换 `su -M -c` → **393216**。证明 -M 能逃逸命名空间读到抖音。
  - **关键经验**：Root App 跨读别的 App 的 /data/data 必须用 `su -M`（mount-master）；adb 的 su 默认在全局命名空间所以一直能读，具有迷惑性。
