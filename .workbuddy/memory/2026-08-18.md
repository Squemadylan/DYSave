- 目标仓库是 Python 项目（抖音全量 API 逆向 + Cookie 认证 + 直播/私信 WebSocket）。代码不能直接塞进 Android，但**思路可复用**。

- 复用结论：
  - 直接复用代码：否（Python≠Kotlin）。
  - 思路复用：是。分两档——
    - Tier1（快、无需 a_bogus）：新增抖音 Cookie 字段，复用 XHS 的 CookieManager 登录/粘贴模式，附加到现有 iesdouyin iteminfo/页面请求，提升 WAF/限流成功率。直接满足"填 Cookie"诉求。

## 用户新需求：自动获取 Cookie（抖音+小红书）
- 用户嫌手动粘贴 Cookie 复杂，想"直连已装 App 自动获取"。
- 现有 XhsLoginActivity / DouyinLoginActivity 已是 WebView 一键登录 + CookieManager 自动抓取（无需粘贴），但首次仍需手输账密。
- Android 沙箱限制：非 Root/无 Shizuku 无法读别家 App 的 Cookie。候选方案：
  1. WebView 一键登录（已实现，半自动）—— 推荐先用。
  2. Shizuku + run-as 读目标 App Cookie 库（免 Root，最现实的"全自动"）。
  3. Root 直读 /data/data/<pkg> Cookie DB。
  4. 本地 VpnService 抓包（SSL Pinning 难绕，不推荐）。
  5. 官方 OAuth（Douyin Open SDK 已有骨架但个人无 client_key；XHS 无开放平台）—— 不可行。
- 待用户选方案；倾向先确认"WebView 登录是否够用"，不够再做 Shizuku。

## 自动获取 Cookie 方案评估与决策
- 用户希望"直连 APP 自动获取 Cookie"（抖音+小红书），避免手动粘贴。
- 方案评估：
  - Shizuku (run-as)：免 Root 读取原生 App Cookie，但 API 复杂、需预装 Shizuku App、且抖音 Cookie 是 Base64 编码的 XML，解析难度高。
  - VpnService + MITM：抖音/小红书有 SSL Pinning，抓不到明文。
  - Root 直读：需要 Root 权限，用户设备未必支持。
- **最终决策**：保留 WebView 一键登录方案（已实现），暂不做 Shizuku。
  - DouyinLoginActivity：WebView 打开 douyin.com，检测到 sessionid_ss/sid_guard/sid_tt 后自动保存。
  - XhsLoginActivity：同理，检测 web_session 后保存。
  - 后续如需 Shizuku，可再评估。

## Shizuku 自动获取 Cookie 方案验证结果
